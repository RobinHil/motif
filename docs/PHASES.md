# Motif - roadmap

Rule: one phase at a time, in order. A phase is done when **all** its criteria are checked and `typecheck`, `lint` and `test` pass. **[SPIKE]** tasks produce a note in `docs/DECISIONS.md` before moving on.

---

## Phase 0 - Foundations and investigations

**Goal**: a clean skeleton and proof that Strudel plays offline inside Electron.

- Initialize the project with Bun, electron-vite, React, strict TypeScript, Tailwind v4, ESLint, Prettier, Vitest.
- Folder structure from `CLAUDE.md`, app name (Motif), tagline and version defined in `src/shared/app-info.ts`.
- Electron security: `contextIsolation`, `sandbox`, CSP, minimal preload, MIDI permission.
- Geist and Geist Mono served locally.
- Tokens from `DESIGN.md` declared in Tailwind's `@theme`.
- `motif-sample://` protocol with path traversal protection.
- Initialize Strudel and superdough, play `s("bd sd hh sd")` with a local sample and `note("c3 e3 g3").s("sawtooth")`.
- **[SPIKE]** Tap on the master output for an `AnalyserNode` and recording.
- **[SPIKE]** Feasibility of per-orbit analysis.
- **[SPIKE]** Live highlighting: how `@strudel/codemirror` works and which positions the transpiler returns.
- Check the `license` field of the installed `@strudel/*` packages and align our `package.json` with it (`AGPL-3.0-only` or `AGPL-3.0-or-later`).
- Generate a `THIRD_PARTY_LICENSES` file automatically from the dependencies, and ship the OFL license of the Geist fonts alongside them.
- Create `README.md` with a "License & credits" section that credits Strudel and TidalCycles and states that the Motif name and logo are not covered by the AGPL.
- Create `SECURITY.md` (private vulnerability reporting through GitHub).
- CI: `ci.yml`, `package.yml`, `codeql.yml`, `audit.yml`, dependency update bot, protection of `main` (see CI/CD in `CLAUDE.md`).

**Acceptance criteria**
- [ ] `bun run dev` opens the window, a button starts and stops the test pattern
- [ ] Sound works with the network disconnected
- [ ] A test checks that `motif-sample://../../etc/passwd` is rejected
- [ ] All 3 spikes are documented with a decision
- [ ] `bun run package` produces a working installer for the current OS
- [ ] `package.json` license matches the Strudel packages
- [ ] `THIRD_PARTY_LICENSES` is generated by a script and includes the Geist OFL license
- [ ] `README.md` has the "License & credits" section
- [ ] `SECURITY.md` exists and explains private reporting
- [ ] `ci.yml` is green on Ubuntu, Windows and macOS
- [ ] `package.yml` uploads installers for the 3 OSes
- [ ] Actions pinned by SHA, minimal permissions, `main` protected

## Phase 1 - Model, code generation, state

**Goal**: the whole logical core, without an elaborate UI.

- Types from `SPEC.md` section 3, defaults, demo project factory.
- Complete `codegen/` per `SPEC.md` section 4, with every snapshot test listed there.
- Zustand store (project, UI, transport) and undo/redo, with continuous gestures grouped.
- Engine: debounced `evaluate`, error handling that keeps the last valid pattern, `lineMap`, playback position.
- Project save and open (project folder), migrations, recovery autosave.

**Acceptance criteria**
- [ ] The demo project generates exactly the expected code (snapshot)
- [ ] `codegen/` coverage above 90%
- [ ] An error injected in a free code track does not stop the sound and is reported with the right track id
- [ ] Save then reopen yields an identical project (test)
- [ ] 200 edits followed by 200 undos return to the initial state (test)

## Phase 2 - Studio screen

**Goal**: build a complete loop with the mouse.

- App shell: transport bar, tabs, global shortcuts, home screen.
- Track list: add, delete, rename, reorder, color, M and S.
- Step grid: click, drag painting, step menu (velocity, probability, variant), canvas playhead.
- Note track preview and free code block.
- Synced code panel (read-only CodeMirror) with the selected track highlighted.
- Inspector: sound source, complete `Knob` component (see behavior in `SPEC.md` 6.1), transforms with editable arguments.
- Sound browser with preview and drag and drop onto tracks.
- Canvas track meters.
- `e2e.yml`: Playwright in CI, including the "zero outbound requests" test.
- **Logo**: propose 3 symbol directions as described in `DESIGN.md` (Logo and brand identity), wait for the owner's choice, then produce the SVG deliverables in `resources/brand/` and use them in the transport bar and home screen.

**Acceptance criteria**
- [ ] Matches `docs/mockups/1-studio.png`
- [ ] Logo chosen by the owner, SVG deliverables in `resources/brand/`, used in the app
- [ ] Every interaction changes the sound within 200 ms
- [ ] The profiler shows zero React re-renders during playback without interaction
- [ ] The whole screen is keyboard-operable
- [ ] End-to-end test: create a track, enable 4 steps, check the generated code
- [ ] `e2e.yml` is green and required for merging into `main`

## Phase 3 - Free code and code editor

- Code editor screen: sidebar, writable CodeMirror, syntax highlighting, `Ctrl+Enter`.
- Live highlighting of played elements.
- Autocompletion and documentation panel from `resources/docs/functions.en.json` (60 functions to start).
- Error console with fix suggestions.
- "Direct edit" mode in Studio and read-back into the UI (canonical format parser, otherwise conversion to free code with confirmation).
- Snippets.

**Acceptance criteria**
- [ ] Hand-editing a track while keeping the canonical format updates the grid
- [ ] A non-canonical edit offers conversion and never loses the typed text
- [ ] `lfp` is fixed to `lpf` by the Fix button
- [ ] Highlighting follows the music with no perceptible lag

## Phase 10 - Export and distribution

- Real-time WAV export of the master, length selection.
- Stems if the phase 0 spike validated them.
- Code-only export.
- `release.yml`: tag `v*.*.*` builds the 3 OSes, `SHA256SUMS`, draft release with changelog, signing when secrets exist.
- Packaging for Windows, macOS, Linux with the name Motif, `.motif` document association, About window with licenses and Strudel credits.
- Generate the icon sets (`.icns`, `.ico`, Linux PNGs) from the approved `icon.svg` with a script (`bun run icons`) and wire them into the packaging config. Also use a document icon for `.motif` folders where the OS supports it.

**Acceptance criteria**
- [ ] The exported WAV sounds identical (no clicks, correct length)
- [ ] Installers work on a machine with no development tools and no network
- [ ] Pushing a `v0.1.0` tag produces a complete draft release with installers and checksums
- [ ] The Motif icon shows correctly in the dock/taskbar, the app launcher and the installer on each OS
